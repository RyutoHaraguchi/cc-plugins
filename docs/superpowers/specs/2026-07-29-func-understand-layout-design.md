# func-understand: グラフレイアウト整理(エッジ交差の削減) 設計スペック

- 日付: 2026-07-29
- 対象: `plugins/cc-func-understand`(v0.3.0 フォローアップ、issue #6)
- 起点: 依存が多い関数を解析するとエッジが縦横に交差して読みにくい(2026-07-29 実利用スクリーンショットで確認)。ユーザーの要望は「ノード・エッジが綺麗に並んでいること」。

## 実測プローブの結果(設計根拠)

実利用グラフ `corelink` の `updateTikTokShopProducts`(137 ノード / 210 エッジ、テスト除外後 112 ノード / 161 エッジ)を dagre で直接レイアウトし、viewer.js のノード寸法・初期可視ロジックを模倣してエッジ交差数を計測した。

| 設定 | 初期表示(31 ノード / 39 エッジ) | 全展開(112 ノード / 161 エッジ) |
|---|---|---|
| 現状(LR、デフォルト) | 交差 21 | 交差 406 |
| ranker: tight-tree / longest-path | 21 / 14 | 438 / 415(悪化) |
| rankDir: TB | 18 | 409(幅 14000px 超で実用外) |
| **align: DL + nodeSep: 20** | **13(-38%)** | **361(-11%)**、エッジ総長 -21%、面積 -36% |

結論:

- `align: 'DL'` + `nodeSep: 20` が全指標で最良。`ranker` はデフォルト(network-simplex)維持。
- 全展開状態で残る数百の交差は層状レイアウトの構造的限界であり、オプション調整では消えない。そのため「交差を減らす」レイアウト調整に加えて、「体感の読みやすさを上げる」選択時デクラッタを併用する。
- ELK 等の別エンジンは交差最小化に強いが、自己完結 HTML(現状 ~800KB)へ +1MB 超の埋込増となるため今回は見送り。本設計で不十分な場合の次段として温存する。

Playwright によるスクリーンショット目視比較でも、`align: DL + nodeSep: 20` は明確に整い、taxi ルーティングは「並んでいる」印象がさらに強いことを確認した。

## 決定事項

### 1. dagre レイアウトオプションの変更

`templates/viewer.js` の `render()` のレイアウト呼び出しを次に変更する:

```js
cy.layout({ name: 'dagre', rankDir: 'LR', align: 'DL', nodeSep: 20,
            nodeDimensionsIncludeLabels: true, padding: 30 }).run();
```

- `align: 'DL'`: 同ランク内ノードを下寄せ整列。実測で交差・エッジ長・面積すべて改善。
- `nodeSep: 20`(デフォルト 50): ノード間隔を詰めて面積を圧縮し、長距離エッジを短くする。
- `rankSep` / `ranker` / `rankDir` は現状維持(実測で改善しないか悪化)。

### 2. エッジルーティングを taxi に変更

`CY_STYLE` の edge スタイルを `'curve-style': 'bezier'` → `'taxi'` に変更する。

- 根拠: 全展開スクリーンショット比較で、bezier は放射状のスパゲッティになるのに対し、taxi は直角配線で「並んでいる」印象が明確に強い。
- 既知のトレードオフ: 密集部で縦の幹線が視覚的に重なり、個々のエッジを追いにくくなる。これは決定事項 3 の選択時デクラッタで緩和する。
- 埋込 cytoscape は 3.30.4 で taxi 対応済み(3.10+)。ライブラリ更新は不要。
- `edge.on-path`(経路ハイライト)や `edge.callback`(破線)のスタイルはクラス側の定義のままで taxi と共存できる。

### 3. 選択時デクラッタ(近傍フォーカス)

ノードをタップ選択したとき、そのノードの 1 ホップ近傍以外を減光して注目部分を追いやすくする。

- 状態: `dimFocus`(選択中ノード id または null)を viewer の状態として持つ。
- 発動: ノードのタップで `dimFocus = id`。対象は「自身 + 接続エッジ + その両端ノード」で、それ以外の可視ノード・エッジに `.dimmed` クラス(opacity 0.15 程度、viewer.css に追加)を付与する。
- 解除: 背景(キャンバス)タップで `dimFocus = null`、`.dimmed` を全解除。詳細パネルは閉じない(パネル開閉は issue #7 の範囲)。
- 初期表示では発動しない: 起動時の `showDetail(graph.target)` は programmatic 呼び出しであり、全体像を損なわないため `dimFocus` は設定しない。タップ操作でのみ発動する。
- 再描画との整合: `render()` は要素を全再構築するため、描画後に `dimFocus` が可視なら減光を再適用する(ダブルタップ展開後もフォーカス維持。展開で追加されたノードは近傍なので減光されない)。`dimFocus` が非可視になった場合は解除する。
- 経路ハイライトとの整合: 経路ハイライト(entry select)変更時は `dimFocus` を解除する(経路全体を見る機能のため)。また `.on-path` が付いた要素は減光対象から除外する。

### 4. テスト

`scripts/test/smoke.spec.mjs` に追加する:

- ノードをタップすると非近傍要素に `.dimmed` が付与される。
- 背景をタップすると `.dimmed` が全解除される。
- 既存 smoke(描画・展開・検索等)が引き続き通ること。

交差数の定量プローブは一時検証(scratchpad)であり、リポには含めない。計測結果は本スペックに記録済み。

## 変更対象

- `templates/viewer.js`: レイアウトオプション、edge スタイル、デクラッタ状態・ハンドラ
- `templates/viewer.css`: `.dimmed` スタイル
- `scripts/test/smoke.spec.mjs`: デクラッタの動作テスト
- `.claude-plugin/plugin.json`: version 0.4.0
- `README.md`: 操作説明(選択でフォーカス、背景タップで解除)の追記

解析エンジン(`analyze-callgraph.mjs` / `lib/`)と `generate-html.mjs` は変更しない(ライブラリ追加なし・サイズ増ゼロ)。

## スコープ外

- ELK 等の別レイアウトエンジンの導入(本設計で不十分な場合の次段候補)
- 詳細パネルの開閉・横幅調整(issue #7)
- エッジ集約(バンドリング)やノードのファイル別グルーピング
