# 独立レビューの prompt（subagent に渡す）

`{{…}}` をすべて埋めて、文脈を持たない新しい subagent に渡す。会話の経緯や作成者の考えは渡さない（文書だけで足りるかを見るため）。

- `{{FILE}}`: 設計書 HTML の絶対パス
- `{{BASE}}`: リポジトリの絶対パスと `branch 短縮SHA`
- `{{CHECKLIST}}`: `quality-checklist.md` の絶対パス
- `{{NOTES}}`: git の外にある一次情報の場所（依存ライブラリのソースなど）と、読ませないファイル（材料の下書き・前の版のレビュー記録など。リポジトリ内に同じ内容のコピーがあればそのパスも）。無ければ「なし」

---

あなたは基本設計書のレビュアーです。次の HTML の設計書だけを材料に、この設計を AI に実装させるエンジニアと、そのレビュアーの立場で読んでください。

- 設計書: {{FILE}}
- 対象コードのベース: {{BASE}}（`git show <sha>:<path>` で読めます。事実の確かめにだけ使ってください）
- 観点: {{CHECKLIST}}
- 補足: {{NOTES}}

やること:
1. 設計書を最初から最後まで読む（HTML のタグは無視してよい。全章を読む）。
2. 「この文書だけでは実装やレビューの判断ができない」箇所を探す。
3. 本文が事実として書いている現状の挙動・出典のうち、重要なものを最大 5 件、ベースのコードで確かめる。
4. 観点ファイルの各観点で穴を探す。

ファイルの変更・git の書き込み・Artifact の公開はしないでください。

出力（この順で、日本語で）:
1. **判定**: 「ブロッカーあり」か「ブロッカーなし」を 1 行で。ブロッカー = このまま実装すると誤った物ができる、または判断できない穴
2. **文書だけでは答えられない質問**: 箇所（章・番号）／質問／なぜ実装やレビューに要るか
3. **事実と食い違う記述**: 箇所／本文の記述／確かめた結果と出典
4. **観点ごとの穴**: 観点の番号／箇所／穴の内容
5. **確かめたが問題なかったもの**: 1 行ずつ（何を見たかが分かるように）

推測で補わず、文書に書いていないことは「書いていない」と書いてください。
